# glidecube — a test case for the Glide path

The counterpart to `wglgears` for OpenGL: a rotating, Gouraud-shaded cube with a depth
buffer, plus the frame rate and what `grSstQueryHardware` reports.

The reason for this program: Quake 1 and Quake 2 only reach Glide through the MiniGL
shim `3dfxgl.dll`, and its `wglCreateContext` fails (`docs/LOG.md` [102]). There is no
ready-made Glide test program anywhere — `testqmfx.exe` from the SoftGPU ISO is, despite
its name, a WGL test [105]. So here is one of our own, speaking to `glide2x.dll`
**directly**.

## Layout

    src/glidecube.c   the program
    src/glidemin.h    the smallest subset of the Glide 2.x interface
    Makefile          three build routes
    build/            build output, not in git

`glidemin.h` is deliberately written from scratch rather than taken from the 3Dfx SDK or
from OpenGLide: the SDK version in OpenGLide pulls in a `sdk2_unix.h` generated by
`configure` that is not in the source tree at all, and for MinGW it defines `FX_ENTRY` as
`extern "C"` — which is C++ and breaks in plain C. Every value in `glidemin.h` is checked
against `sdk2_glide.h` and `sdk2_sst1vid.h` from OpenGLide.

## Building

### Host, against OpenGLide

```sh
make host
make run
```

That way the program can be checked **before** a VM is even running — OpenGLide translates
Glide into OpenGL on the host and opens an X11 window of its own.

### Guest, cross build with MinGW

```sh
make win32
```

MinGW needs an import library. The makefile generates it from the wrapper's built
`glide2x.dll`: `gendef` reads the exports, `dlltool` turns them into `libglide2x.a`. Two
switches are mandatory:

- `-march=prescott -mtune=core2` — the guest runs with `-cpu coreduo`, and SSE3 is the
  ceiling.
- `-mcrtdll=msvcrt-os` — without it the toolchain links against the UCRT, which does not
  exist under Windows 9x. The makefile prints the DLL dependencies as a check; there must
  be no `api-ms-win-crt-*` among them.

### Guest, Visual C++ 6.0

For building in the guest itself. Needs `glide2x.lib` — either from the 3Dfx SDK or
generated from `glide2x.dll` with `IMPLIB`.

```
cl /W3 /O2 /I. glidecube.c glide2x.lib /Fe GLIDECUB.EXE
```

That is why the source is plain C89: declarations at the start of a block, no `//`
comments, no C99 constructs.

## Usage

```
glidecube [seconds] [resolution] [-info] [-vsync]
```

- **seconds** — run time, default 15. `0` means endless.
- **resolution** — 320, 512, 640 or 800. Default 640.
- **-info** — print the hardware data only, draw nothing.
- **-vsync** — wait for the vertical retrace. **Without** this switch the frame rate
  measures throughput; with it, it measures the screen's refresh rate.

## What the program shows

- `grSstQueryHardware` — whether the far side reports a card at all, and with what data.
- The cube itself — that triangles are rasterised, colours interpolated across the
  surface and hidden faces sorted out through the W buffer.
- The frame rate — as a measure of whether anything is really being accelerated.

## Two pitfalls that came up while building it

**Transparent window.** In Glide the write mask for the alpha channel defaults to **off**.
On the host OpenGLide picks a GLX visual with eight alpha bits; if the channel stays at
zero, the compositor takes the window to be transparent. The remedy:
`grColorMask(FXTRUE, FXTRUE)`.

**Racing rotation.** The rotation angle must not depend on the number of frames. At over
15,000 frames per second on the host that turns into useless flickering, and the display
would look different on every machine. The angle therefore follows elapsed time.

## Configuring OpenGLide

On its first start OpenGLide creates `OpenGLid.ini` in the working directory. Two values
in it explain what `-info` reports:

    FrameBufferMemorySize=8      -> "Frame buffer 8 MB"
    TextureMemorySize=16         -> "TMU0: 16 MB"

`Resolution=0.0` means original size; a value above 16 sets a fixed width and scales the
output up. The file does not belong in git, it is created afresh on every run.
